# Proposed block for the DataOS Comprehensive Review prompt: golden-demand check (E15)

WHAT THIS IS: a paste-ready block of prompt text for the **DataOS Comprehensive Review** (saved prompt #145 "Latest_comprehensive", used by both review steps of spec 231 (the DataOS pipeline spec id) "ManualQC automated QC pipeline NO CLAUDE", a pipeline that is now retired). It is NOT a GitHub script. It is a proposal: nothing on DataOS has been changed, so no pipeline uses this block and it does not block a task. Testing it needs a cloned spec (a new saved prompt set on both review steps) and one 10-task run on dataset 3424; creating the saved prompt and the spend are Khiem's calls. The hold-review lane is drafting the other prompt edits (E1 to E14, severity definitions and verdict rules); this block is meant to sit in the same full prompt as a separable paragraph, so a test arm with it and an arm without it differ by this block only.

WHY (evidence, all from labelled QC data; see GOLDEN_REVIEW_EVIDENCE.md in this folder):
- About 73 percent of manual-QC MAJOR items are criteria that demand something the instruction never asks for or pin the golden's own reading; most of them are criteria every model run failed.
- In the 25 TFRL-rejected tasks (tasks the human TFRL QC team rejected) with a current DataOS review, 6 have no major finding. Two of those (619, SVC-PC-45-4-0) were found by the review as a 1.4 misalignment (review check 1.4: the rubric grades something the instruction never asked for) but rated minor.
- A reviewer shown the golden and told to check whether the instruction covers the criterion (even broadly) found 20 of 33 TFRL-confirmed defect criteria at 6.0 percent false flags when run as an outside script; the same test is the missing mandatory step inside the review.
- Caveat: when the golden review was tested as an outside gate it added one catch for three blocks on the 19 tasks that overlap the DataOS reviews, and the first independent verdicts on held-out flags confirmed 2 of 68. Only a DataOS run on the clone can show whether this block helps inside the review.

BLOCK (paste after the 1.4 checks, before the severity rules):

> **Golden-demand check on every criterion that every model run failed.** Use the full test matrix (all tests, not the first 100). Judge only the current version of the task's tests. For each such criterion: (1) list each figure, assumption, alternative, analysis, label, structure or reading the criterion demands that appears in the golden; (2) search `instruction.md` and the sources for each item, counting broad wording ("anything missing", "each affected file", "file by file", "where two files disagree") as coverage; (3) if an item is found only in the golden, or the criterion contradicts an explicit instruction sentence, report a **1.4 major** naming the criterion id, quoting the criterion and the closest instruction sentence; (4) otherwise classify it as a genuine model miss and name the instruction or source sentence that covers it. Do this for every such criterion, not a sample, and list each with its classification.

SCORING THE TEST: per task, majors on the 5 TFRL-rejected tasks of dataset 3424 versus majors on the 5 TFRL-passed tasks, against the existing control run (#962, prompt #145 unchanged). The earlier v1-control result was 9 of 10 blocked, so the block must not raise blocks on the passed tasks.
